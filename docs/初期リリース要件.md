# スタディングキャリア 初期リリース要件

2026年10月22日。LPから相談・紹介の申込みを受け付け、人による面談・求人紹介でサービスを開始するシナリオ。ユーザーの方針に基づく要件案であり、利用ツール・担当体制・公開文言は確定前。

## 1 最初に提供するサービス

**資格・学びを活かしたい人が申し込み、担当者と話して、合う求人の紹介を受けられるサービス。**

初期版の「登録」は、相談・人材紹介サービスへの申込みを意味する。ログイン用アカウントは発行しない。求職者が使う主な画面は、1ページのLPとページ内フォーム、送信後の完了表示とする。連絡・日程調整・面談・求人紹介は、運営が利用する既存ツールで実施する。

前の [コンセプト構想](コンセプト構想.md) は中長期の方向として保持する。初期リリースでは、学びがキャリアにどうつながるかを人が支援し、その実績と利用者の声を次の機能設計に使う。

## 2 最小の利用シナリオ

1. スタディング内の案内・メール・広告などからLPへ来る。
2. 対象者、支援内容、無料で利用できる範囲、申込後の流れを理解する。
3. 最小限の情報と同意を入力して申し込む。
4. 完了表示と受付メールを確認する。
5. 担当者が連絡し、面談日時と方法を調整する。
6. 面談で経験・資格・学習・希望を確認し、本人に合う求人を紹介する。
7. 応募を希望する求人ごとに意思と提出情報を確認し、担当者が選考・入社まで支援する。

即時予約は必須にしない。既存の予約ツールが稼働確認済みなら、受付完了後に予約リンクを案内する。未整備なら担当者のメール調整で開始する。求人を紹介できない場合や、転職をまだ希望しない場合の対応も事前に決める。

## 3 LPの構成案

| 順序 | セクション | 伝える内容 |
| --- | --- | --- |
| 1 | 最初の画面 | 「資格・学びを、次のキャリアへ。」と無料相談の申込ボタン |
| 2 | 対象者の悩み | 資格の活かし方が分からない、学習中でも転職できるか相談したい、仕事と学習を両立したい |
| 3 | 支援すること | 経験・学習の整理、キャリアの相談、条件に合う求人紹介、応募・選考の支援 |
| 4 | 利用の流れ | 申込 → 担当者からの連絡 → 面談 → 求人紹介・応募支援 |
| 5 | 対応する領域 | 実際に求人供給と支援体制がある資格・職種・地域のみ記載 |
| 6 | 安心して申し込むための説明 | 利用料金、情報の取扱い、希望確認、支援できない場合があること |
| 7 | よくある質問 | 学習中・未経験・転職時期未定の利用、面談方法、書類、費用、申込後の連絡 |
| 8 | 申込フォーム | 最小項目、同意、送信ボタン |
| 9 | 運営情報 | 運営会社、必要な事業情報、利用条件・個人情報の取扱い、問い合わせ先 |

主要ボタンは「無料でキャリア相談を申し込む」に統一する。受付だけで求人検索やスカウトが利用できるように見せない。本人の応募意思を確認する運用が整っていれば「応募は希望を確認してから進めます」と伝える。実績・求人例・利用者の声は掲載権限と根拠があるものに限る。

スマホを優先し、見出しと短い説明、読みやすい余白、押しやすいボタンで構成する。長いアニメーションや複雑な診断は初期範囲に含めない。ページ内の申込位置へ移動でき、入力エラーでも値が消えないことを基本品質にする。

## 4 申込フォーム

| 項目 | 初期案 | 理由 |
| --- | --- | --- |
| 氏名 | 必須 | 担当者が連絡・面談するため |
| メールアドレス | 必須 | 受付連絡と日程調整のため |
| 電話番号 | 任意 | 電話を希望する人の連絡先。電話中心の体制なら必須化を検討 |
| 関心のある資格・学習中／保有資格 | 必須 | 複数選択。「未定・その他」も選べる。科目等の詳細は面談で確認 |
| 今の相談内容 | 必須 | 「資格の活かし方」「学習中・未経験の転職」「求人紹介」「その他」等から選択 |
| 希望する勤務エリア | 任意 | 支援対象を絞る必要がある場合は必須化。住所の詳細は求めない |
| 自由記入 | 任意 | 伝えたいことだけ記入。個人番号や第三者の機密等を書かない案内 |
| 利用条件・個人情報の取扱いへの同意 | 必須 | 文言と版を確定し、同意した内容と時点を記録 |

初期申込みでは、生年月日、詳細住所、学歴、全職歴、希望年収、職務経歴書、パスワードを求めない案とする。支援の適否や求人応募に必要な情報は、面談・応募準備の段階で確認する。必要性がある項目は、その時点で追加できるようにする。

メール広告等の追加配信を行う場合は、サービス提供のための連絡と区別し、必要に応じて別の任意選択を設ける。未選択のまま送信できるようにする。資格・相談内容は単純な選択肢で開始し、高機能な検索UIや現行全資格マスタの完全移植を必須にしない。

## 5 最小システム構成と運用

**LP → 既存のフォーム・顧客管理ツール → 担当者 → メール／予約ツール → オンライン面談** を第一候補にする。既存ツールの適合を確認して選び、独自の会員・管理システムを初期の前提にしない。

| 構成 | 必要なこと | 最速化の考え方 |
| --- | --- | --- |
| LP | HTTPS、スマホ対応、フォームへの導線 | 静的ページや既存CMSを利用可能 |
| 申込受付 | 保存、受付ID、重複対策、入力確認 | 既存の業務フォーム・CRMに接続。通知メールだけを保存先にしない |
| 受付連絡 | 完了表示、受付メール、担当者への通知 | 実在する連絡先と次の流れを表示。機密情報をメールへ過剰に転載しない |
| 管理台帳 | 担当、状態、対応予定、履歴 | 既存CRM・ATSを優先。適切な権限設定ができる台帳でも開始可能 |
| 面談 | 日程調整、会議URL、記録 | 既存メール・オンライン会議を使用 |
| 求人紹介 | 案件情報と本人の応募意思の管理 | 担当者が個別連絡。求人の公開検索は不要 |
| 計測 | 流入元、申込、面談、求人紹介、応募・入社 | LPと運営台帳を受付IDで対応させる |

システムを作る範囲より、既存の運用基盤を何に接続できるかで速度が決まる。採用・紹介業務で使っているCRMやATSがあれば、フォーム受付とつなぐ案から評価する。具体的な外部製品は、契約・個人情報の取扱い・現在の利用状況を確認して選ぶ。

### 管理台帳の最小項目

受付ID、受付日時、申込情報、同意文言の版と日時、流入元、担当者、状態、次回対応予定、最終連絡日時、面談日時、紹介求人、応募意思確認、選考・入社の状況、辞退・連絡停止等の記録。面談記録・提出書類は、管理権限のある保管先へ分けて保存してもよい。

連絡の状態は「新規受付 → 連絡中 → 面談予約 → 面談実施 → 継続支援／対応終了」を基本とする。求人紹介・応募・選考の状態は求人ごとに持ち、複数案件がある人を一つの状態で上書きしない。

重複申込みは、同じメールという理由だけで黙って削除しない。受付として記録したうえで、担当者が同一人物かを確認し、既存履歴と対応づける。送信の連打・通信再送は別途二重受付を抑止する。

### 公開前に決める運営の約束

- 受付確認の担当と不在時の代行、連絡予定の目安、休日の扱い。
- 面談の対応可能枠、担当者、求人を紹介できる分野・地域。
- 支援対象外・連絡不達・相談のみ・中断の対応方法。
- 紹介先への情報提供、応募意思確認、書類送付の手順。
- 情報訂正・申込取消・連絡停止の窓口と処理方法。
- 旧サービスで進行中の案件と新規申込みの担当・履歴のつなぎ方。

これらは運用上の決定事項。連絡予定や支援範囲を確定するまで、LPで即日対応・必ず求人紹介等を約束しない。人材紹介の運営主体、対象範囲、利用条件、表示情報・個人情報の取扱いは、現行契約と担当者の確認を経て公開文言へ反映する。

## 6 初期版で必要な機能と後から追加する機能

| 初期版に入れる | 後から追加する候補 |
| --- | --- |
| LPとページ内の申込フォーム | 会員登録・ログイン・マイページ |
| 入力チェック、二重送信対策、迷惑送信対策 | 求人検索・詳細・キープ |
| 申込保存、受付ID、同意記録 | スカウト・サイト内メッセージ |
| 完了表示と受付メール、社内通知 | スタディングとの個人情報の自動連携・SSO |
| 担当・履歴・次回対応の管理 | AI診断・プロフィール作成・推薦 |
| 流入・申込・面談等の計測 | 企業ポータル、独自予約システム |
| 運営情報・問い合わせ・規約等の導線 | 学びのパスポート、先輩対話、実務体験 |

予約ツールへのリンクは、利用できる既存環境があれば初期版へ追加できる。申込完了と予約完了は別に計測し、予約しなかった人も担当者がフォローできるようにする。

求人情報は、個別紹介を始められることが初期の要件。求人の掲載システムや法人による求人登録画面は、最初の公開に必須ではない。選考・成果・請求の管理は既存の紹介業務で継続する。

## 7 スタディングからの送客

初期は「講座・資格ごとの文脈がある案内 → LP内の関連説明 → 相談申込」に絞る。同じLPでも「簿記を学んだ先の仕事を相談」「資格学習と両立できる転職を相談」等、入口のメッセージを変えられる。

学習サービスとの個人データ連携がなくても、許可されたバナー・メール等と、個人情報を含まない流入パラメータで検証できる。流入情報を使って資格の選択欄へ候補を表示する場合も、本人が確認・変更できるようにする。URLに氏名・メール・会員ID・試験結果を入れない。

まず記録するのは、どの案内から来たか、申込み、面談予約・実施、求人紹介、応募、入社。クリック数だけで送客効果を判断せず、対応工数と支援の成立も見る。学習中の表示は学習を妨げない場所と頻度から始める。

## 8 リリースまでの進め方と受入確認

1. 運営体制、支援対象、使う受付・管理・面談ツールを決める。
2. LP原稿、申込項目、同意文言、受付メール、連絡の目安を確定する。
3. 既存ツールにつないだLPを実装し、計測・権限・保存先を設定する。
4. テスト申込みから面談案内・求人紹介の記録まで一通り確認する。
5. 対象を限定して公開し、受付量と対応状況を見て送客を増やす。

期間の見積りは、利用基盤・公開審査・連携先・担当者の確定後に行う。既存ツールが整っていれば、独自の会員システム開発を待たずに公開する方針とする。

| 確認事項 | リリース時の条件 |
| --- | --- |
| 正常申込み | 完了表示、受付ID、保存データ、本人メール、社内通知が対応する |
| 障害 | 保存失敗時に成功と表示しない。通知失敗を検知でき、保存済み受付を再送できる |
| 入力と再送 | 必須・メール形式・文字数を確認し、エラーでも値を保持。連打・再送で意図せぬ二重受付を抑止 |
| 情報管理 | 公開ページや解析へ申込内容が漏れず、台帳・書類は権限のある担当者だけが閲覧できる |
| 同意 | 何に同意したか、いつ申し込んだかを受付と対応づけて確認できる |
| 端末 | 代表的なスマホ・PCで閲覧、入力、送信、メール内リンクを確認する |
| 運営引継ぎ | 新規申込が担当へ届き、不在・対象外・連絡不達でも対応予定が残る |
| 計測 | 個人情報を含めずに流入と申込完了を記録し、台帳で面談以降を追える |

旧サービスの閉鎖と新LPの公開は別に管理する。旧URLの転送・終了求人・既存会員への案内・進行中案件の引継ぎを決め、LPだけで過去案件が失われないようにする。

## 9 高度化する順序

| 段階 | 追加するもの | 追加を判断する根拠 |
| --- | --- | --- |
| 初期 | LP、申込、有人支援、運営台帳 | まず相談と求人紹介を実施できる |
| 運営改善 | 予約、連絡リマインド、CRM連携 | 日程調整や未対応確認に負荷が出る |
| 求職者の自己管理 | プロフィール更新、書類提出、希望変更 | 情報回収・更新の往復が増える |
| 求人との自己接点 | 求人検索、キープ、応募、まず話す | 紹介可能な求人供給と、本人が探す需要が確認できる |
| マッチング強化 | スカウト、学びのパスポート、推薦 | 候補者・企業の量と情報品質が整う |

各段階は公開後の学びで変更できる。将来に備えて最初から残すのは、受付ID、同意、流入、担当・接点・案件の履歴。初期から将来の全機能を実装することを避ける。

## 10 次に具体化するもの

この案を基に、次は「LPの掲載原稿」「フォームの最終項目」「受付メール」「担当者の対応フロー」を作る。実装方式を決めるために必要なのは、現在使っているCRM・ATS・予約・メール等のツールと、初期に紹介できる資格・職種・地域の範囲。これらの確定前でもLP原稿と画面構成は進められる。
