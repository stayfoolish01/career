# スタディングキャリア 再構築のためのサービス調査と要件整理

調査日：2026年10月21日（日本時間）。対象：求職者向け公開サイト、企業向け案内、FAQ、会員登録入口、規約、相談・エージェント導線。閉鎖予定は依頼者からの情報で、閉鎖日は未確定。

**再構築で保持すべき核は、資格と学習状況を起点にしたマッチング、スタディング会員連携、直接応募とスカウト、相談と学習による転職支援である。** 特に匿名公開から応募・返信による情報開示への切り替え、企業ブロック、企業と紹介事業者の区別を先に設計する。成功報酬とスカウト枠の運用も業務要件に含める。

本資料は要件定義のたたき台。公開説明を確認したことと、ログイン後の動作を実証したことは区別する。「確認」は公開ページに記載・表示があるもの、「提案」は新システム向けの設計案、「要確認」は社内資料や実画面が必要なものを表す。優先度は提案であり、承認済みの開発範囲ではない。

## 1 サービスの特徴と事業構造

| 特徴 | 公開情報から確認した内容 | 新システムへの示唆 |
| --- | --- | --- |
| 資格を軸にした転職 | 資格保有者と学習者を企業・転職エージェントにつなぐ。2023年11月7日リリース [S02](https://studying.jp/career_release.html) | 学習段階から登録・接点形成できる |
| 資格の状態が細かい | 資格検索に登録済・全科目合格・科目別合格・免除・一次合格等がある [S06](https://career.studying.jp/kyujin/search-detail) | 「資格名」だけのマスタでは不足する |
| 学習サービスとの連携 | 登録済み資格情報を引き継ぐ説明。会員登録入口はスタディングへの無料登録または既存アカウントでのログインを案内 [S02](https://studying.jp/career_release.html) [S11](https://member.studying.jp/career/signup/) | 会員ID対応、連携項目、同意、同期方式を確定する |
| 能動・受動の両方の転職活動 | 求人検索・応募、スカウト、提携エージェント、無料動画 [S03](https://career.studying.jp/column/about) | 今すぐ転職する人と情報収集中の人を支援する |
| 運営による相談 | 約30分の無料オンライン相談。求人・エージェント紹介、書類・面接支援、転職しない人への学習・キャリア計画支援 [S14](https://career.studying.jp/column/careersupport) | 相談申込と予約、面談記録、紹介の運用が必要 |
| 企業向けの課金 | 初期・月額0円、入社時の成功報酬。月次スカウトを一定数無料付与、翌月への繰越不可、求人掲載無制限と説明 [S05](https://career.studying.jp/column/corporation) | 成果報告・請求と、月次枠の残数・期限を管理する |

成功報酬率、無料スカウト数、返金条件、紹介事業者との契約条件は公開ページから確定できない。ページにある学習者数・合格者数・講座数は掲載時点が揃わないため、新基盤の容量設計には用いない。トップと取得した詳細検索では約2.1万件の検索件数表示を観測したが、これは取得時点の表示値であり、移行対象件数やユニーク求人件数とは限らない。

## 2 利用者と主要業務

| 利用者 | 実行する業務 | 主な画面・情報 |
| --- | --- | --- |
| 未登録の求職者 | サービス理解、求人・エージェント検索、相談・会員登録へ進む | トップ、検索、求人詳細、案内・FAQ |
| 求職者会員 | プロフィール・資格・職歴登録、応募、スカウト返信、メッセージ、書類提出 | マイページ、応募履歴、通知設定、企業ブロック |
| 採用企業 | 求人登録、候補者検索、スカウト、選考・採用報告 | 法人アカウント、求人審査、候補者・選考管理。実画面は要確認 |
| 紹介事業者 | 候補者への接触、相談受付、求人紹介、進捗報告 | 採用企業とは異なる契約・求人・成果帰属を持つ |
| 運営・採用サポート | 法人審査・発行、原稿審査、相談、返信催促、成果確認・請求 | 公開案内に業務説明あり。管理画面・権限・操作記録は要確認 |
| スタディング側担当 | 会員・資格・動画システムの連携管理 | IDと資格データの責任範囲、連携障害対応は要確認 |

求職者の基本導線は「登録 → プロフィール等の入力 → 求人応募またはスカウト返信 → 選考・面接 → 内定入社」。運営相談と提携エージェントへの相談は別の入口を持つ。企業の開始手順は「問い合わせ → 申込書・社員権限の決定 → 運営がアカウント発行 → 導入打合せ → 求人登録・運営審査 → 掲載・スカウト」である。公開案内は導入まで4〜5営業日程度としている。[S03](https://career.studying.jp/column/about) [S05](https://career.studying.jp/column/corporation)

提携エージェント一覧は得意業界・職種で探す構成で、個別紹介と相談申込を持つ。相談申込先に `/kyujin/数値ID` を利用する例があり、求人と相談募集が同じ導線に載っている。移行では求人種別と相談受付を区別して抽出する。[S07](https://career.studying.jp/column/agent-list) [S66](https://career.studying.jp/kyujin/229636)

求人詳細の例では、自由記述の応募資格に簿記2級以上の必須条件、別項目の「活かせる資格」に多数の税理士科目等を掲載している。したがって、活かせる資格タグを必須応募条件と同一視しない。検索給与は年収を案内する一方、求人本文には月給・年俸等があるため、数値・単位・換算ルールを分ける。[S70](https://career.studying.jp/kyujin/258525)

## 4 個人情報と業務ルール

### 公開説明で確認した情報開示

| 状態・情報 | 公開範囲 |
| --- | --- |
| 学歴・希望条件・経験スキル | 登録企業・採用エージェントに公開。ただしブロック済み法人を除く |
| 氏名・生年月日 | 求人応募またはスカウト返信時に公開 |
| メールアドレス・電話番号 | FAQでは開示しないと説明 |
| ブロック | 法人名検索から設定。対象は現在掲載中の法人のみ |

出典：[FAQの個人情報公開範囲](https://career.studying.jp/column/faq)。この記述は通常の求人・スカウト導線の説明として扱う。規約には、面談希望時に本人または運営が紹介事業者へ登録情報を提供することも記載されている。相談経由の提供項目・同意と、求人応募時の開示を別に確認する。[S08](https://career.studying.jp/policy?policy_no=7)

自由記述の職歴や添付ファイル自体に氏名・連絡先を記入できるため、構造化項目の非公開だけでは匿名性を保証できない。新システムでは、候補者検索用の匿名情報、応募先に提出する書類、運営内の相談情報を分け、項目別・相手別・状態別の開示を検証することを提案する。

### 移行時に見落としやすい現行仕様

- 応募前に求人について質問する機能はない。
- 応募辞退は相手へのメッセージで伝える方式。専用の辞退状態更新機能があるとは断定できない。
- 一度辞退した求人に、メッセージや応募履歴から再応募できると案内。
- 応募の1通目ではメッセージのやりとりができないという説明がある。自己アピール欄や応募後の送信との関係は画面で確認する。
- プロフィール上で職務経歴書の複数登録は不可。一方、応募先ごとの書類変更を案内しており、共通書類と提出書類の実データ構造は要確認。
- 返信は応募翌日から5営業日以内を依頼。5営業日経過後は問い合わせに応じ運営が催促する。自動催促の実装は確認できない。
- 匿名スカウトのため、過去応募先や同一法人から再びスカウトが来ることがある。
- 会員は原則1人1アカウント。海外在住者も登録可能。FAQは日本語以外のサービスがないと説明。

以上の出典：[S04](https://career.studying.jp/column/faq)。これらは再現すべき仕様と改善すべき制約を決めるための材料であり、すべてをそのまま残すという提案ではない。

## 5 新システムの機能要件候補

詳細は `requirements.csv`。各行に優先度、現行根拠、検討事項、受入確認の例を付けた。P0は再開時の基本業務・情報保護・切替に必要と考えるもの、P1は支援・運営効率に関わるもの、P2は改善案。

| 分類 | P0で先に固める内容 | P1以降の候補 |
| --- | --- | --- |
| 会員・認証 | スタディングIDとの対応、資格情報連携、プロフィール・職歴、退会・停止、権限 | 入力進捗、更新促進 |
| 求人 | 構造化求人・資格マスタ、検索・詳細、企業と紹介事業者の区別、審査・掲載期間 | 特集・関連求人・回遊改善 |
| 応募 | 本人確認、応募内容と提出書類の保全、履歴、再応募、返信 | 辞退状態の明示・選考進捗表示 |
| スカウト | 匿名検索、法人ブロック、受信・返信時の開示、月次枠 | テンプレート・重複抑制 |
| 法人・運営 | 法人契約・社員権限、求人審査、成果把握、既存選考の引継ぎ | 返信催促、集計、問い合わせ処理 |
| 相談・学習 | 再開範囲と既存連携を確定 | 予約・面談・紹介、動画・コンテンツ運用 |

AI推薦、自動スカウト、AI書類添削、外部ATS連携、企業自己登録、オンライン決済の存在は今回の公開資料では確認していない。導入する場合は追加要件として扱う。

## 6 データ構造と連携の検討材料

以下は提案する論理データの分け方であり、現行DBの調査結果ではない。

| データ | 持つべき情報の候補 | 移行で確認する点 |
| --- | --- | --- |
| 会員・外部ID | 会員ID、スタディングID、認証状態、連携同意 | IDの一意性、重複、認証移行、メール変更の扱い |
| 資格・学習 | 資格、等級、科目・段階、取得／学習状態、日付、情報源 | 現行の複合ラベルを損なわず新マスタに変換する |
| 法人・担当者 | 法人ID、採用企業／紹介事業者、契約、担当者、権限 | 同一法人の複数サービス・担当者、退職者の無効化 |
| 求人 | 掲載法人、採用主体、種別、条件、資格タグ、審査、期間 | エージェント求人と相談募集の区別、終了求人 |
| 応募・提出書類 | 求人・会員・相手、応募日時、自己アピール、提出時点の内容、書類版 | 最新プロフィールで過去の応募情報を上書きしない設計を検討 |
| スカウト・メッセージ | 相手、求人、本文、送受信、既読、添付、開示イベント | 関係者以外へ表示しない、スレッド・添付の対応 |
| ブロック・同意 | 会員×法人、設定時点、提供先・項目・目的・規約版 | 旧ブロックIDの維持、解除や退会の履歴 |
| スカウト枠 | 法人、対象月、付与、消費、失効、調整履歴 | 月境界、同時送信、送信失敗時の戻し、繰越禁止 |
| 成果・請求 | 応募／紹介経路、選考、入社日、年収、報酬条件、請求・返金 | 成果帰属、既存選考、請求済・未請求を引き継ぐ |
| 相談・コンテンツ | 相談予約・担当・紹介先、公開記事、動画・閲覧条件 | 相談情報の閲覧権限、動画元データと配信権利 |

公開導線には `career.studying.jp`、会員登録・動画の `member.studying.jp`、画像等の `careerwp.studying.jp`、CloudFront、公開YouTube、予約用短縮URLがある。これはURL上の観察であり、現行基盤やベンダー製品を特定するものではない。SSO方式、API、バッチ、Webhook、メール配信・解析・求人取込の構成は社内確認が必要。

## 7 非機能要件の論点と受入確認

数値目標は現行ログ・契約・事業計画で決める。公開求人件数だけから性能や可用性を決めない。

| 項目 | 要件化する内容 | 確認例 |
| --- | --- | --- |
| 権限と情報開示 | 法人間分離、会員本人のみの編集、ブロックと返信時開示 | 別法人IDでURL・API・添付を直接参照しても閲覧できない |
| 添付書類 | 容量・拡張子、検査、保存先、期限付き取得、削除 | 期限切れURL・別応募先から書類を取得できない |
| 操作記録 | 開示、書類取得、運営参照、契約・枠・請求変更 | 誰がいつ誰の情報を扱ったか追跡できる |
| 安定運用 | 監視、連携失敗検知、再実行、バックアップ・復旧 | 応募や通知の再処理で二重応募・二重送信が起きない |
| 検索性能 | データ量、同時利用、対象条件、応答目標 | 合意した代表条件・負荷で測定する |
| モバイル | スマホで検索・応募・書類・相談まで完了 | 主要端末で文字入力、添付、エラー復帰を確認 |
| SEO・公開URL | 主要流入URLの維持／転送、終了求人、サイトマップ | 上位流入URLと旧求人URLの移行対応を点検 |
| 通知 | 種別別の停止、必須通知の定義、再送、送信記録 | 停止設定を移行後も守り、未読・返信通知を重複送信しない |
| 保持・退会 | アカウント停止とデータ削除の区別、各データの保存期限 | 退会が学習アカウントに及ぼす影響と、相手側履歴を確認 |

規約・個人情報の取扱いは保存した現行文書と、新運用・契約・適用ルールを担当者が照合して決める。本資料は法的適合性の判定をしていない。

## 8 閉鎖前に確保するもの

| 優先 | 確保するもの | 担当候補 | 完了条件 |
| --- | --- | --- | --- |
| 最優先 | 停止日、閲覧停止日、データ取得期限、保守・旧基盤解約日 | 事業責任者・旧ベンダー | 作業期限を日付で確定 |
| 最優先 | DB項目定義、全件エクスポート、添付ファイル、ID対応、マスタ | 開発・旧ベンダー | 件数・関連・文字コード・添付実体を照合し復元可能 |
| 最優先 | 会員・法人・運営のログイン後画面と主要操作動画 | 運営・開発 | 登録から応募・返信・ブロック・審査・採用報告まで記録 |
| 最優先 | 進行中応募・相談・選考、未読、入社予定、未請求、スカウト残数 | 運営・経理 | 相手と担当者を含む引継ぎ台帳を作成 |
| 最優先 | ブロック、公開設定、同意履歴、通知停止、退会・削除状態 | 開発・個人情報管理担当 | 移行対象外と禁止事項を含め検証できる |
| 高 | 企業・紹介事業者契約、料金表、成果判定・返金・請求規程 | 営業・経理 | 契約別に新基盤へ持ち込む条件を確定 |
| 高 | 求人取込、ID連携、メール・予約・動画等の仕様とテンプレート | 開発・運営 | 接続先、データ責任、頻度、失敗時手順が分かる |
| 高 | CMS記事・画像・動画原本、掲載権利、旧URLとSEOログ | コンテンツ・マーケ | 再掲載できる原本と転送先を確保 |
| 高 | 利用規約・同意文言の版、配信除外、運営ルール・FAQ | 運営 | 過去の適用条件と現行条件を識別できる |

現時点では公開資料の保存まで実施した。会員個人データ、管理画面、契約書、動画本体、基盤設定・ソースコードは取得していない。これらは公開サイト収集では代替できず、閉鎖前の社内取得が必要。

切替は「試行移行 → 件数・関係・開示の照合 → 進行中案件の合意 → 書込み停止と差分移行 → 新基盤の受入 → DNS・URL切替 → 監視」を提案する。中断期間や並行稼働の要否、戻す条件は別途決定する。旧メール通知や予約導線の停止も切替項目に含める。

## 10 保存資料と利用方法

`sources.csv` が出典台帳。`manifest.json` にURL、取得時刻（UTC）、HTTP状態、転送先、SHA256、リンク・画像・フォームを記録した。本文は `sources/Sxx.txt`、受信したHTML等は `sources/Sxx.html`。HTMLは外部資産に依存するため完全なオフライン画面再現ではない。閉鎖後の参照はテキストと保存画像を優先する。スクリーンショットやログイン後画面の保存は含まない。

74件の取得試行のうちHTTP 200は71件（robots.txtを含む）。残りはサイトマップ404、抽出されたjavascriptリンク1件、相談予約の遷移先503。主要ページと提携エージェント個別紹介44ページ、求人詳細のサンプル等を保存した。全求人・全記事の完全バックアップではない。

画像は60URLを試行し20件を保存、40件は404だった。失敗先は `assets_manifest.json` に残した。予約の短縮URLは取得時点でTimeRexのメンテナンス案内（503）へ遷移し、予約フォームの項目と完了フローは確認できていない。これらの原本・現行設定は社内での確保を優先する。

`requirements.csv` は要件の検討表、`form_fields.csv` は公開HTMLの入力項目、`index.html` はローカル保存資料の索引。再取得用スクリプトも同梱。取得時のフォームトークン等を含むため、原HTMLやmanifestをそのまま公開配布せず、社内の移行資料として扱う。
